# 保留历史记录的 Ink 终端尺寸调整

[English](./ink-resize.md) | [日本語](./ink-resize.ja.md) | [简体中文](./ink-resize.zh-CN.md)

## 依赖补丁的应用

[`ink+7.1.1.patch`](../../patches/ink+7.1.1.patch) 会在安装开发依赖后、build／watch 之前，以及
`npm test`／`npm run test:it` 之前，通过 `npm run patch:dependencies` 自动应用。
安装钩子仅在补丁文件和本地 `patch-package` CLI 均存在时运行。
发布包已经内置应用补丁后的 Ink，不包含这些开发文件，因此发布包的安装钩子不需要开发依赖。
开发环境中应用补丁失败时，安装也会失败。
Nix 会在重新创建生产依赖树后直接重新应用补丁。
Ink 的版本固定，并随 npm 发布包一同打包，因此 TAKT 分发的是构建时已经应用补丁的 renderer。

安装开发依赖后，可以在仓库根目录应用或重新应用补丁：

```sh
npm run patch:dependencies
```

## 实时绘制的尺寸调整等待

主屏幕上的交互式 TTY 收到尺寸调整事件后，会暂停实时绘制，直到最后一次事件后经过 150ms，
并取消已排队的旧宽度帧。
尺寸稳定后，只清除自己管理的实时区域，再按新尺寸重绘当前输入区和状态行。
不清空屏幕或滚动历史，也不重复输出已确定的 `<Static>` 条目：既有历史由终端管理。
连续调整尺寸后最终回到原始宽度的情况也采用同样的处理。
主屏幕下的全屏回退路径同样只清除实时区域的行，并输出新增的已确定内容，
而不是清空历史并重新输出整段对话。

## 正文重新折行与限制

`TranscriptView` 显式使用补丁新增的 `<Static renderOutput>` 来输出终端内容。
每个新条目直接从已过滤控制字符的原始正文序列化，不插入 Ink 根据显示宽度生成的固定换行或填充空格。
因此，缩小或扩大宽度时，终端可以重新折行用户发言和 AI 回答的段落，包括滚动历史中的段落。
正文中明确的换行仍作为固定换行保留。
终端自动折行产生的续行从左边缘开始；明确换行产生的续行则保留标记列的缩进。
用户发言的背景带通过在正文**之前**清除到行末来绘制，而不是用空格填满整行。
正文恰好到达右边缘后再清除到行末时，如果终端将等待折行的光标限制在最右列，最后一个字符可能被擦除。
调整尺寸时不会重新填色已经绘制的背景空白区域。
旧 renderer 已经输出的固定换行也会保留；不替换终端历史就无法修复它们。
非 TTY 和屏幕阅读器输出使用常规 React children，而不是终端专用的序列化处理。

## 实时区域的光标锚定

仅任务会话的挂载向 `mountInk()` 传入 `{ anchorLiveFrame: true }`。
manager、辅助提问和 dispatch 的挂载保持 Ink 默认的绘制选项。
隐藏的真实终端光标保持在实时区域的**顶部**（第一行，或一行边框的正下方），整个帧构成一个软换行行组。
Xterm 类终端会将光标所在的行组留给应用自行重绘。
终端高度缩小时，会丢弃光标下方的实时行，而不是将前面的输入框或 `Thinking`（思考中）行推入滚动历史。
清除操作从该光标向上移动其上方已绘制的行数后向下清除，绝不修改上方已确定的行。
终端重新折行或裁剪行时不会调整 DECSC 保存的位置，因此不使用 DECRC。
绘制前先分配空白行，然后关闭自动折行，从下往上绘制。
即使在 PTY 输出分块的中途调整尺寸，也不会将已绘制的实时行推入光标上方的历史。
Unicode 字符宽度差异和制表符也不会产生不受控制的额外实时行。
结束清理时会清除自己管理的区域。
此选项优先于增量绘制。

任务会话将编辑器的**光标行**放在输入区上边框的正下方。
`useCursor()` 将真实光标放在该行的日语 IME 插入列。状态、通知、队列、补全、提示和模型都位于光标下方。高度较小时，通知和队列优先于上下两行边框。
光标之前的输入行被折叠，输入区下方的 `↑ N` 表示前方的显示行数。上下键仍可编辑这些行，提交和交接保留完整原始缓冲区。
此显示变更仅用于任务会话，不改变其他提问界面或 manager 的布局。

仅保存第一行的位置，再将真实光标移到下方，无法保护其上方的实时行。
终端可能在高度缩小时、应用收到调整通知并清除之前，将这些行归入历史。
xterm.js 会先删除光标下方的行，因此光标上方的一行边框可保留到高度 2 行。
因此，直接使用 Ink 时，硬件光标位于第一行或第二行的帧也会采用软换行行组 renderer，即使未指定 `anchorLiveFrame`。
自动选择仅在主屏幕交互式 TTY 中、绘制实时帧之前进行。更靠下的硬件光标继续使用常规／增量 renderer。
为调整尺寸或确定输出而清除时保留光标意图，避免 IME 位置消失直到下一次编辑。
输出超过屏幕高度时裁剪下方；仅当否则放不下光标行时，才省略光标上方的行（边框）。

### 输入宽度与确认行

输入区仅在显示时将保留的制表符绘制为一个空格。换行、上下移动和真实光标采用相同显示宽度，提交与交接仍保留原始制表符。
等待 provider 确认时，优先在输入区下方预留一行，再分配状态和可选装饰。确认文字经过单行净化，并按终端宽度截断。
高度为1〜2行时只能容纳输入行，扩大窗口后显示确认文字。Ctrl+C/Ctrl+D 先拒绝待确认操作，再等待进行中的处理结束。

### IME确认与Enter的输入契约

Ink 的 `useInput()` 提供文字和按键标志，不提供 IME 组合状态。
终端将日语确定文字作为文本发送时（包括同一文本事件内附带CR的情况），只插入草稿，另一个 Return 事件才提交。chat 与 summarize 的回归测试覆盖这些不同输入事件。
若终端把转换确认作为独立的单个CR发送，该事件与提交用的Enter无法区分。时间或日语字符启发式无法可靠地区分两者。
支持这种情况需要终端／IME专用的组合状态通知及真实输入记录；现有测试不保证在所有环境中检测转换确认Enter。

### macOS Terminal.app

实测表明，Terminal.app 与 xterm.js 类终端（Orca、VS Code）有三点不同：
它也会重新折行包含光标的行组；光标跟随重新折行后的内容；高度缩小时保留光标下方的行，并将上方的行归入历史。
DECSC 保存的位置不随重新折行调整，因此不恢复保存位置，而是根据光标在重新折行后行组中的位置求出帧的首行。

缩小宽度会使占满整行的行组变高（5 行 120 格在 60 列下变为 10 行）。
若只从锚点清除再重绘，多出的行会作为空行留在新帧下方。
下一次缩小高度时，Terminal.app 会保留这些空行，转而将输入区上部归入历史。
当 `TERM_PROGRAM` 为 `Apple_Terminal` 时，显式指定锚定绘制的会话挂载还会启用 `reflowsCursorGroup`；其他挂载不传入此选项。
行组 renderer 根据已绘制的内容计算新宽度下的行数；光标越过新宽度而折行时，也会计算光标所在行。
重绘在重新折行后行组的末尾结束，多出的行成为同一行组开头的空白行。
扩大宽度时 Terminal.app 会连同这些空白重新折行，下一次确定输出也从这些行开始写入，因此空白不会累积。
脚手架只填充帧最后一行的一个单元格，因此之后重新折行时按实际绘制的单元格计数，而不是按填满的整行计数。
若重新折行后的行组高于窗口，可见行全部属于旧帧，因此清除屏幕（不清除滚动历史），并在屏幕底部绘制帧。

仍有一个限制：若新窗口不高于（重新折行后的）输入区域，Terminal.app 会在 TAKT 收到通知前保留光标下方的行，并将上方的行归入历史。
例如 120×30 → 60×8，或单行输入时高度约 6 行（折叠的多行草稿为 7 行）：上边框会留在历史中，低于约 5 行时光标行也会留下。
清除滚动历史会删除用户的历史，因此这些行保留在历史中。

其他帧未启用此选项时，`log-update.js` 补丁会按当前终端宽度重新计算上一帧的行数，
包括带 ANSI 样式的填充区域和宽字符。
常规 renderer 和增量 renderer 会先恢复硬件光标相对于重新折行后帧的位置，再执行清除。

## 生命周期与绘制回退

暂停绘制期间确定的输出会排队保留，不会丢弃。
显式输出／flush、clear、暂停和卸载操作会先完成待处理的尺寸调整，再接管终端。
卸载时会取消定时器，避免延迟帧覆盖选择器或在退出后继续输出。
等待已经卸载的实例退出时，也不会注册新的进程退出监听器。
备用屏幕、debug、非 TTY 和屏幕阅读器绘制保持既有的尺寸调整路径。

## 回归测试

[`src/__tests__/tui-conversation-view.test.tsx`](../../src/__tests__/tui-conversation-view.test.tsx) 中的回归测试会检查整个终端模拟器缓冲区，
包括既有的 shell 滚动历史。
覆盖宽度缩小和扩大、快速连续调整尺寸、回答生成期间的 `/go` 草稿、硬件光标、
包含表情符号和制表符的多行草稿下的高度缩小、带队列的日语输入光标位置（高度 1／2／3／5／6 行）、Terminal.app 中在重新折行后行组末尾结束的重绘（包括高于窗口的情况，且反复调整尺寸时空白行不会增加）、PTY 帧输出中途调整尺寸、
正文恰好到达右边缘的用户发言、调整尺寸期间确定的输出、全屏切换、卸载、带队列的交接和任务执行。
[`e2e/specs/tui.e2e.ts`](../../e2e/specs/tui.e2e.ts) 还会调整真实 PTY 的尺寸，在不重复输出历史的前提下，
检查屏幕外的历史、从选择器返回后的重新挂载，以及实时输入区和 `Thinking` 状态。
测试会在窄终端中确定英语和日语的用户发言及 AI 回答段落，并验证扩大宽度后它们重新变成单行。
PTY 回归测试还会在反复调整这些段落的显示宽度时，检查较早的屏幕外消息仍被保留。
真实 PTY 的高度回归测试会检查空闲和回答生成期间的多行草稿，覆盖终端缩小至 8 行／6 行以及重新扩大，
并确保 70 行已确定的历史各自只保留一次。
另一项真实 PTY 测试检查高度 1／2／3／6 行时日语插入位置的真实光标，并确认折叠不会改变多行提交内容。
这些光标测试不观测 macOS IME 的未确定文字或候选窗口；实际 IME 仍需通过 GUI 单独验证。
