# 履歴を保持する Ink のリサイズ処理

[English](./ink-resize.md) | [日本語](./ink-resize.ja.md) | [简体中文](./ink-resize.zh-CN.md)

## 依存パッチの適用

[`ink+7.1.1.patch`](../../patches/ink+7.1.1.patch) は、開発用依存関係のインストール後、build／watch の前、
`npm test`／`npm run test:it` の前に、`npm run patch:dependencies` によって自動適用されます。
インストールフックは、パッチファイルとローカルの `patch-package` CLI の両方が存在する場合にだけ実行します。
公開パッケージにはパッチ適用済みの Ink を同梱し、これらの開発用ファイルは含めないため、
公開パッケージのインストールフックは開発用依存関係を必要としません。
開発環境でのパッチ適用に失敗した場合は、インストール自体も失敗します。
Nix では本番用依存ツリーを再作成した後、パッチを直接再適用します。
Ink のバージョンは固定し、公開 npm パッケージに同梱するため、build 時にパッチ適用した renderer が TAKT とともに配布されます。

開発用依存関係をインストールした状態で、リポジトリのルートから適用・再適用できます。

```sh
npm run patch:dependencies
```

## ライブ描画のリサイズ待機

メイン画面の対話型 TTY でリサイズイベントが発生した場合、最後のイベントから 150ms が経過するまで
ライブ描画を停止し、古い幅で予約されたフレームを取り消します。
サイズが落ち着いたら、自分が所有するライブ領域だけを消去し、現在の入力欄と状態表示を新しいサイズで再描画します。
画面やスクロールバックは消去せず、確定済みの `<Static>` エントリも再出力しません。
既存の履歴は端末が管理します。連続したリサイズの最後に元の幅へ戻る場合も、この処理で対応します。
メイン画面での全画面フォールバックも、履歴の消去や会話全体の再出力は行わず、
ライブ領域の行だけを消去して、新しい確定出力だけを出力します。

## 本文の再折り返しと制約

`TranscriptView` は、端末への出力にパッチで追加した `<Static renderOutput>` を明示的に使用します。
各新規エントリは、制御文字を除去した元の本文から直接文字列化し、Ink の表示幅に依存する固定改行や空白埋めを挿入しません。
そのため、幅を狭めたり広げたりすると、スクロールバック内でもユーザー発言と AI 回答の段落を端末が再折り返しできます。
本文に明示された改行は固定改行として保持します。
端末の自動折り返しによる継続行は左端から始まり、明示改行による継続行ではマーカー分のインデントを保持します。
ユーザー発言の背景帯は、空白文字で幅を埋めるのではなく、本文の**前**に行末までの消去を行って塗ります。
本文がちょうど右端まで届いた後に行末消去を行うと、折り返し待ちのカーソルを端末が右端へ制限した際に、最後の文字が消えることがあります。
過去に塗られた背景帯の余白は、リサイズ時には塗り直しません。
旧 renderer がすでに出力した固定改行も残ります。端末の履歴を置き換えずに修復することはできません。
非 TTY とスクリーンリーダー向けの出力では、端末用の文字列化処理ではなく、通常の React children を使用します。

## ライブ領域のカーソル固定

タスク会話のマウントだけが `mountInk()` に `{ anchorLiveFrame: true }` を指定します。
manager・補助プロンプト・dispatch のマウントは Ink の既定の描画オプションを使います。
非表示の実カーソルをライブ領域の**上端**（先頭行、または 1 行の枠のすぐ下）に保持し、フレームをソフトラップされた 1 つの行グループとして構成します。
Xterm 系の端末は、カーソルがある行グループをアプリケーションによる再描画に任せます。
高さが縮んだときは、先頭の入力欄や `Thinking`（「考え中」）の行をスクロールバックへ押し出すのではなく、
カーソルより下にあるライブ領域の行を破棄します。
クリア処理は、このカーソルからその上に描いた行数だけ戻って下を消去し、上にある確定済みの行には触れません。
端末は折り返しや行の切り詰めで DECSC の保存位置を調整しないため、DECRC は使いません。
描画前に空の行を確保し、自動折り返しを無効にして下から上へ描画します。
PTY の出力チャンクの途中でリサイズされても、描画済みのライブ行がカーソルより上の履歴へ押し出されることはありません。
Unicode の文字幅の違いやタブによって、意図しないライブ行が追加されることも防ぎます。
終了処理では、所有する領域を消去します。
この設定は差分描画より優先されます。

タスク会話では、入力欄の上枠のすぐ下に入力の**キャレット行**を置きます。
`useCursor()` で、その行の日本語 IME 入力位置へ実カーソルを合わせます。
状態・通知・待機キュー・補完・操作ヒント・モデルはすべて入力位置より下へ置きます。高さが小さいときは、上下 2 行の枠より通知と待機キューを優先します。
キャレットより前の入力行は折り畳み、入力欄の下側にある `↑ N` で前方の表示行数を示します。
上下キーで折り畳まれた行も編集でき、送信・引き継ぎでは入力バッファ全体を保持します。
この表示変更はタスク会話だけの設定で、他の質問画面や manager の配置は変更しません。

先頭位置を保存して実カーソルを下へ移すだけでは、その上の行は保護できません。
端末は高さ縮小時、アプリケーションが消去する前にそれらを履歴へ移すことがあります。
xterm.js はカーソルより下の行から削るため、キャレットの上にある 1 行の枠は高さ 2 行まで残ります。
そのため、直接 Ink を使う場合でも、1 行目か 2 行目に実カーソルを持つフレームは `anchorLiveFrame` の指定にかかわらず行グループ方式で描画します。
自動選択はメイン画面の対話型 TTY で、ライブフレームを描く前にだけ行います。それより下の実カーソルは既存の通常／差分 renderer を維持します。
リサイズや確定出力のための消去でも入力位置を保持し、次の編集まで IME 用の位置指定が失われないようにします。
出力が画面高さを超えた場合は下側を切り詰めます。カーソルより上の行（枠）は、そうしないとキャレット行が入らないときだけ省きます。

### 入力幅と確認行

入力欄では、保持したタブを表示時だけ1つの空白として描きます。折り返し・上下移動・実カーソルは同じ表示幅で計算し、送信・引き継ぎには元のタブを保持します。
provider の確認待ちは、入力欄の下の1行を状態表示や任意の装飾より先に確保します。確認文は1行に無害化し、端末幅で切り詰めます。
高さ1〜2行では入力行しか収まらないため、確認文は拡大後に表示します。Ctrl+C/Ctrl+D は確認を拒否してから進行中の処理を待ちます。

### IME確定とEnterの入力契約

Ink の `useInput()` が渡すのはテキストとキーのフラグで、IME変換中の状態は渡されません。
端末が日本語の確定文字をテキストとして渡す場合（同じテキストイベント内にCRを含む場合も）、下書きへの挿入だけを行い、別のReturnイベントで送信します。chat・summarize の両経路でこの区別を回帰テストします。
端末が変換確定を独立した単独CRとして送る場合、そのイベントは送信用Enterと区別できません。時間や日本語文字の有無による推測では確実な区別はできません。
この場合の対応には、端末・IME固有の変換状態通知と実際の入力トレースが必要です。既存テストは、すべての環境で変換確定Enterを検出できるとは保証しません。

### macOS ターミナル.app

ターミナル.app は、実測で次の 3 点が xterm.js 系の端末（Orca、VS Code）と異なります。
カーソルを含む行グループも折り返し直すこと、カーソルが折り返し後の内容に追従すること、高さを縮めるとカーソルより下の行を残して上の行を履歴へ移すことです。
DECSC の保存位置は折り返しに追従しないため、保存位置へ戻らず、折り返し後の行グループ内でのカーソル位置からフレームの先頭行を求めます。

幅を縮めると、画面幅いっぱいの行グループは縦に伸びます（120 セルの 5 行は 60 列で 10 行）。
起点から消去して描き直すだけでは、伸びた分が新しいフレームの下に空行として残ります。
次に高さを縮めたとき、ターミナル.app はその空行を残し、代わりに入力欄の上部を履歴へ移します。
`TERM_PROGRAM` が `Apple_Terminal` のとき、明示的にアンカー描画を指定した会話マウントは `reflowsCursorGroup` も有効にします。他のマウントにはこのオプションを渡しません。
行グループ renderer は描画済みの内容から新しい幅での行数を計算します。キャレットが新しい幅を超えて折り返された場合は、カーソルの行も計算します。
描き直しは折り返し後の行グループの末尾で終え、余った行は同じ行グループの先頭の空白行にします。
幅を広げるとターミナル.app がこの空白ごと折り返し直し、次の確定出力もこの行から書くため、空白は積み重なりません。
足場はフレームの最終行を 1 セルだけ埋めるため、後の折り返しでは行末までの余白ではなく実際に描いたセル数で数えます。
折り返し後の行グループが画面より高い場合、見えている行はすべて旧フレームなので、画面（スクロールバックではない）を消去してフレームを画面下端に描きます。

制限が 1 つ残ります。新しい画面が（折り返し後の）入力領域より高くない場合、TAKT が通知を受ける前に、ターミナル.app はカーソルより下の行を残して上の行を履歴へ移します。
例は 120×30 → 60×8 や、1 行の入力で高さ約 6 行（折り畳まれた複数行の下書きでは 7 行）です。このとき上枠が、約 5 行未満ではキャレット行も履歴に残ります。
スクロールバックを消去すると利用者の履歴も消えるため、これらの行は履歴に残します。

それ以外でこの設定を使わない場合、`log-update.js` のパッチは、ANSI スタイル付きの余白や全角文字も含めて、
前のフレームの行数を現在の端末幅で数え直します。
通常 renderer と差分 renderer は、再折り返し後のフレームに対するハードウェアカーソル位置を復元してから消去します。

## ライフサイクルと描画のフォールバック

描画停止中に確定した出力は破棄せず、キューに保持します。
明示的な出力／flush、clear、一時停止、アンマウントは、保留中のリサイズを確定させてから端末の制御を引き継ぎます。
アンマウント時にはタイマーを取り消し、遅延フレームがセレクタを上書きしたり、終了後に出力されたりしないようにします。
すでにアンマウントされたインスタンスの終了待ちでも、新しいプロセス終了リスナーを登録しないようにします。
代替画面、debug、非 TTY、スクリーンリーダー向けの描画では、既存のリサイズ処理を維持します。

## 回帰テスト

[`src/__tests__/tui-conversation-view.test.tsx`](../../src/__tests__/tui-conversation-view.test.tsx) の回帰テストは、既存のシェル出力のスクロールバックを含む、
端末エミュレータのバッファ全体を検証します。
幅の縮小・拡大、高速な連続リサイズ、応答中の `/go` の下書き、ハードウェアカーソル、
絵文字やタブを含む複数行の下書きでの高さ縮小、待機キューを伴う日本語入力のカーソル位置（高さ 1／2／3／5／6 行）、ターミナル.app で折り返し後の行グループ末尾に揃える描き直し（画面より高い場合を含み、リサイズを繰り返しても空白行が増えないこと）、PTY フレーム途中のリサイズ、
本文がちょうど右端まで届くユーザー発言、リサイズ中の出力確定、全画面表示との切り替え、
アンマウント、キューを伴う引き継ぎ、タスク実行をカバーします。
[`e2e/specs/tui.e2e.ts`](../../e2e/specs/tui.e2e.ts) では実 PTY もリサイズし、履歴を再出力せずに、画面外の履歴、
セレクタからの再マウント、ライブ領域の入力欄と `Thinking` を検証します。
英語・日本語のユーザー発言と AI 回答の段落を狭い幅で確定し、幅を広げると再び 1 行になることを確認します。
PTY の回帰テストは、これらの段落を繰り返しリサイズする間も、古い画面外のメッセージを保持することを確認します。
実 PTY での高さの回帰テストでは、待機中・応答中の複数行の下書きを 8 行／6 行の端末と再拡大後に検証し、
確定済みの履歴 70 行がそれぞれ 1 回だけ保持されることを確認します。
別の実 PTY テストでは、高さ 1／2／3／6 行でも日本語の挿入位置に実カーソルがあり、折り畳み後も複数行の送信内容が変わらないことを確認します。
これらは macOS IME の未確定文字や候補ウィンドウを観測するテストではありません。実 IME は GUI で別途確認する必要があります。
